# pi-codex-accounts

> ChatGPT Codex 멀티 계정 로테이션 + 한도 시각화 for pi. `429`에서 자동 전환, `5시간/7일` 바와 절대 리셋 날짜, 현재 계정 하이라이트.

## Why

Codex는 계정당 `5시간`과 `7일` 윈도우로 할당량을 잰다. pi는 기본으로 `openai-codex` 한 계정만 쓴다. 한도가 차면 세션이 멈춘다. 이 확장은 `openai-codex`, `openai-codex-account-2`, `openai-codex-account-3` ... 을 하나의 풀로 묶고, 다음을 제공한다:

- **자동 전환과 재개**: 한도 오류에서 소진된 `5시간/7일` 창의 `resetAt`까지 해당 계정을 대기시키고, 사용 가능한 계정으로 전환한다. 일반적인 Codex `usage limit`처럼 Pi가 기본 재시도하지 않는 오류는 `agent_settled` 시점에도 같은 실패로 멈춰 있을 때만 한 번 재개한다
- **현재 실패 응답만 재개**: 같은 세션, 모델, 실패 메시지가 그대로인지 확인한다. 과거 사용자 요청을 찾아 복사하지 않는다. 실패 메시지 ID를 담은 짧은 확장 안내만 추가하고 기존 대화를 이어간다. 새 입력, 대기 중인 메시지, 중단, 세션이나 대화 경로 변경이 있으면 재개하지 않는다. 같은 사용자 요청에서는 계정 수보다 많이 자동 재개하지 않으며, 확장을 다시 불러와도 대화 기록으로 횟수를 확인한다
- **기본 재시도와 분리**: Pi의 공식 오류 판별 함수를 사용한다. Pi가 재시도 대상으로 판단한 오류는 Pi에만 맡긴다. 기본 재시도의 취소, 비활성화, 횟수 제한을 확장의 추가 호출로 우회하지 않는다. 전역 재개 lease는 사용하지 않는다
- **사용량 기록 잠금**: 여러 pi 프로세스가 `codex-account-usage.json`을 동시에 갱신해도 `mkdir` 기반 파일 잠금으로 갱신 유실이 없다
- **한도 시각화**: `/codex-accounts`에서 `https://chatgpt.com/backend-api/wham/usage`를 직접 조회해 `5시간 ███░░ [32% 남음] 리셋 8/28 05:07 (4시간 42분 후) · 7일 █████░░ [49% 남음] 리셋 9/02 20:26 (5일 20시간 후)` 형태로 표시. 절대 날짜 + 남은 시간 함께
- **현재 계정**: 헤더 `│ 현재: go***@naver.com (1번) ●`와 각 줄 `●/○` + `← 현재 사용 중`으로 구분. 목록 진입 전 위젯으로 표를 띄우고 닫으면 자동으로 사라짐 (`setWidget`, `notify` 아님)
- **토큰 카운트**: `~/.pi/agent/codex-account-usage.json`에 계정별 `total / cacheRead`를 5시간 윈도우 기준으로만 누적·리셋. 웹에서 쓴 건 `rate_limit`에는 잡히지만 이 숫자는 pi가 API로 쓴 것만 센다

## Install

```bash
git clone https://github.com/Blue-B/pi-custom-packages.git
cd pi-custom-packages
pi install ./packages/pi-codex-accounts
```

`/reload` in pi.

## Usage

1. `/codex-accounts` — 표 확인 후 짧은 선택 메뉴에서 전환
2. 전환은 `5h:15% · 7d:49%` 형태로 `:` 구분, 상세는 위젯 표에서
3. 자동 전환은 설정 없이 동작한다. 전환된 계정에서도 한도 오류가 나면 다음 가용 계정을 확인하고, 모두 소진되거나 대기 중이면 알림을 내고 멈춘다. 각 세션은 자신이 방금 실패한 응답만 재개하며, 다른 세션이나 재시작 전 요청을 찾아 실행하지 않는다
4. `/model`은 계정을 바꾸지 않는다. 계정 별칭에서 모델을 고르면 그 모델 ID를 유지한 채 현재 계정에 그대로 적용된다. 계정을 바꾸려면 `/codex-accounts`를 쓴다
5. Codex 모델 사용 중 계정만 바꿀 때는 현재 모델을 유지하고 임의의 다른 모델로 낮추지 않는다. DeepSeek 등 다른 제공자 모델 사용 중 `/codex-accounts`에서 계정을 고르면 대상 계정에서 사용 가능한 Codex 모델로 전환하고 선택된 모델을 알린다

계정 추가: `Ctrl+P`에서 `openai-codex-account-3` 선택 → 브라우저 OAuth → 다음 `/codex-accounts`에 3번으로 나타남. 확장은 항상 `가장 높은 번호 +1` 슬롯을 미리 등록한다.

## Notes

- Codex 계정끼리는 현재 모델을 유지한다. 다른 제공자에서 넘어올 때는 Codex 모델을 새로 골라야 하므로, 사용 가능한 모델을 쓰고 전환 알림에 이름을 표시한다.
- 설치 형태: `pi install`로 등록된 패키지다. 소스는 이 저장소이고 `~/.pi/agent/extensions/`에 손 복사본을 두지 않는다. 손 복사본이 남으면 확장이 중복 로드된다.
- 현재 구현은 Pi 0.85.1의 `agent_settled`, 취소 신호, 공식 오류 판별 API로 검증했다. 이전 버전의 모호한 재개 문구가 남은 대화에는 필요한 요청을 직접 명시한다. 현재 실패를 확인하는 장치는 이전 대화의 내용을 지우거나 모델의 해석을 강제하는 장치는 아니다.
- 요청 범위에 대한 안내는 모델의 판단을 돕는 장치이며, 모든 도구 사용을 강제로 막는 권한 장벽은 아니다.
- 업데이트한 확장은 새 Pi 프로세스에서 적용된다. 이미 열린 Pi는 `/reload`가 필요하며, Paseo의 기존 Pi 세션은 새 프로세스로 다시 열어야 적용된다.
- 토큰 표시 `토큰 153M (캐시 149M)`은 이번 5시간 윈도우 누적이며, 윈도우 리셋 시각에 0으로 돌아간다.
- `pi-multicodex` 등 유사 확장이 이미 있다. 이 패키지는 **한국어 UI + 절대 날짜 + 위젯 자동 숨김**에 초점을 둔 가벼운 대체재다.

## Checks

저장소 루트에서 `tsx --test packages/pi-codex-accounts/tests/*.test.ts`를 실행한다. 계정 조회와 모델 응답은 가짜로 넣고 임시 홈을 사용한다. 실제 Pi 로더와 세션으로 한도 오류 후 재개, 기본 재시도 중복 방지, 조회 중 취소, 기본 재시도 대기 중 취소, 전 계정 소진을 검사한다. 실제 계정 한도나 모델 API는 소비하지 않으며, 모델 답변의 정확성을 측정하는 검사는 아니다. 설치본을 검사하려면 `CODEX_ACCOUNTS_ENTRY=/절대경로/codex-accounts/index.ts`를 지정한다.
